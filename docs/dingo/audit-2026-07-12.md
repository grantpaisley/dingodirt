This is an adversarially-verified workflow audit of everything merged since the
2026-07-08 audit (baseline `c108471`): the export crate, the
basket/export/share pipeline, privacy zones, web import, the route drawer +
grades, Strava sync, and the parallel-session harvest/Strava-heat subsystem.
9 subsystem finders → 42 raw findings → dedup → 2 adversarial verifiers each
(default-refute). 70 of 76 verifier votes upheld their finding. The audit was
read-only; it changed nothing.

**Headline: the privacy feature's geometry trim is correct, but private
location data leaks *around* it in several ways, and `/api/export/share` is
remotely triggerable. Fix these before any hosted or shared use.**

---

## HIGH

### H1. `/api/export/share` is an unauthenticated, CORS-open exfiltration endpoint
`crates/daemon/src/routes/export.rs:467`
The daemon has no auth on any `/api` route, and it sends permissive CORS
(`allow_origin(Any)`). While the daemon runs, **any web page the user visits**
can `fetch('http://localhost:3000/api/rides')` to enumerate the ride ids. The
page can then POST `/api/export/share`. The daemon publishes the user's tracks
to a public-readable gist and returns the URL in a CORS-readable body. There is
zero interaction beyond a visit to a page. (The geometry is zone-trimmed, so
home is masked. But the whole route corpus leaks to a durable public URL.)
This is the most serious finding.
*Fix direction:* require a local token / same-origin check for the mutating +
share endpoints, or put share behind an explicit confirmation. At minimum,
tighten CORS to the known web origin.

### H2. Ride names leak the hidden suburb on every export
`crates/daemon/src/routes/export.rs:600`, `crates/export/src/lib.rs:286`
1,066 of 1,133 zone-sensitive rides are named `"Arcadia to …"` / `"Arcadia loop
via …"`. The name ships verbatim in GPX `<name>` tags, filenames, bundle
manifests, and the share gist's bundle.json. This defeats the geometry trim.
Worst case: a **fully-private** ride (geometry 100% suppressed) still puts its
name in the `skipped[]` array published inside the link-readable gist. That
announces `"Arcadia loop 2 kms"` to any link holder. *Fix direction:* scrub
the zone suburb tokens from the exported names/filenames for sensitive rides.
Drop (or anonymize) the names in the shared `skipped[]` list.

### H3. Adding a privacy zone doesn't re-trim already-exported library files
`crates/cli/src/organize.rs:246` (also 289; 3 finders independently)
`export_tree` is incremental: if a ride's `exported_path` file exists, the
export skips it (or only relocates it) without a content regeneration, unless
you pass `--force`. Every ride exported before the privacy feature existed
keeps its full home geometry on disk after `privacy add-place` + `organize`.
This includes now-fully-private rides. Yet the CLI prints *"their exports will
be trimmed"*. The synced library folder keeps leaking after the user believes
it is redacted. *Fix direction:* privacy add/remove must force-regenerate the
affected rides (or `organize` must detect zone-vs-file staleness). The message
must not over-promise. (The "will be trimmed" count is also wrong — it counts
all intersecting rides, but the trim applies only to start/end-inside rides.)

### H4. Organize plants raw untrimmed copies inside the library tree
`crates/cli/src/organize.rs:559`
Phase 4 moves the original source file into `<dest>/Duplicates/` (loose) or
`<dest>/Archives/` (zips). These copies are full resolution, with the home
points included, inside the same library tree that the privacy contract calls
a trimmed egress surface. A ride whose `Recorded/` GPX was trimmed (or fully
excluded) still has its complete raw track in `Duplicates/`. The leak
materializes if the user syncs or shares the whole library root.
*Fix direction:* keep the raw staging folders outside `--dest`, or trim/exclude
the sensitive raws too, or document Duplicates/Archives as never-sync.

### H5. Route drawer crashes (white screen) after a zoom-tier change mid-draw
`web/src/components/Map/MapView.tsx:1000`
`lastSnapRef` stores a vertex **index** into the ride path at the current zoom
tier. `useRides` refetches at a different simplification tier across zoom
11/15, so the same ride's array gets a different length. Snap on ride R at z15.
Zoom out below z11. Click R again. The follow-splice loop then reads
`path[699…60]` and pushes ~640 `undefined` into `drawPath`. The next render
destructures `undefined` → TypeError. No ErrorBoundary exists, so React
unmounts → a white screen, and the in-progress route is lost. The other tier
direction silently saves a **wrong** plan geometry. (I suspected this in the
audit prompt; it is confirmed.)
*Fix direction:* store the snapped lon/lat (+ a tier stamp). Re-resolve the
index against the current path. Drop the follow-continuity when the geometry
identity changed.

## MEDIUM

- **M1. DingoNav corridor bbox uses untrimmed geometry** (`export.rs:699`) —
  `selection_bbox` = `ST_Extent(cleaned_geometry)`. A home-start ride puts the
  home corner into the basemap PMTiles bounds and into the z15 Strava-tile
  corridor shipped in the bundle. An attacker can recover it: add back the
  known 0.015° pad. This holds even for a fully-private ride. *Fix:* compute
  the bbox from zone-differenced geometry, as `dingonav_heat_features` already
  does.
- **M2. `/api/export` `prune_stale` can delete foreign files** (`export/src/lib.rs:539`) —
  there is no ownership check before it recursively deletes non-written `.gpx`
  under the bundle dir. Name a bundle after an existing synced folder (OsmAnd's
  `rec`) and it wipes real recordings. It also follows symlinks out of the
  tree. *Fix:* require a Dingo manifest / an empty dir before the prune. Do not
  traverse symlinks.
- **M3. PATCH commits mode before validating grade** (`rides.rs:707`) —
  `{mode:"mtb",grade:9}` writes the mode (+ `mode_source='user'`, which blocks
  future auto-reclass), then 400s on the grade. Thus an error response hides a
  persisted write. *Fix:* validate both, then update in one transaction.
- **M4. DingoNav/share panics on a NULL-named ride** (`export.rs:584`) —
  `dingonav_tracks` does `r.get::<String>("name")` with no COALESCE. A
  web-imported ride whose naming failed (a NULL name) drops the connection on
  every export that contains it. *Fix:* read the name as `Option<String>` (as
  build_bundle does).
- **M5. Strava tile cap not enforced at a single zoom** (`export.rs:845`) —
  `while total>cap && by_zoom.len()>1` stops at one zoom, even if that zoom
  holds tens of thousands of tiles. "Select all" + include_strava → ~40k
  sequential authenticated Strava fetches from your account. *Fix:* apply the
  cap absolutely, or reject over-wide corridors.
- **M6. Strava sync: no rate-limit handling** (`strava_sync.rs:241`) —
  the default `--limit 200` blows the 100-req/15-min quota at about activity
  95. The 429 aborts before clean/name, which leaves the imports raw. *Fix:*
  add backoff + Retry-After. Run clean/name in a `finally`-style block.
- **M7. Strava sync: failed activity is skipped forever** (`strava_sync.rs:188`) —
  the watermark = max(started_at) advances past a transiently-failed activity
  on the next run → a permanent silent gap. *Fix:* track a low-water mark, or
  record the failures.
- **M8. Zip source-tag watermark mistags concurrent imports** (`organize.rs:483`) —
  `UPDATE … WHERE imported_at >= mark AND source IS NULL` sweeps up any ride
  ingested (web import, `dingo ingest`, strava) during the zip run. Host-clock
  vs Postgres-`now()` drift also mis-windows the update. *Fix:* tag by the
  ride ids that the zip actually produced (ingest_zip must return them), not
  by a time window.
- **M9. Mode PATCH doesn't invalidate `allRideMeta`** (`DetailPane.tsx:102`) —
  the Places tree keeps stale type/counts (and a folder click selects the
  stale set) for up to 5 min after a mode change. The grade paths *do*
  invalidate it, so this is an omission. *Fix:* add
  `allRideMeta`/`rideLocations` to the mode invalidations.
- **M10. Heat overlay raster source has no `maxzoom`** (`MapView.tsx:767`) —
  MapLibre requests z14+ tiles that the harvester never produced (max z13/14).
  Thus the blue "everyone else" heat blanks out exactly at trail-inspection
  zoom. *Fix:* set the source `maxzoom` to the archive max, so MapLibre
  overzooms.

## LOW (selected)

- The import handler leaks its scratch temp dir (the uploaded contents) on
  every call — `remove_dir_all` cleans it only on some paths (`import.rs:59`).
- A `create_plan` clean failure leaves a committed but invisible plan
  (`rides.rs:205`).
- The grade filter hides rides from the layer + the list, but not from the
  density heatmap (`MapView.tsx:444`). The direction chevrons ignore the dim
  context (`MapView.tsx:348`).
- The mousemove handler wipes the draw-mode crosshair cursor on the first move
  (`MapView.tsx:1063`).
- `GET /api/heat` with `y >= 2^z` → a subtract-overflow panic in the TMS flip
  (`heat.rs:33`).
- The Strava cookie paste is rejected wholesale if any `;`-segment lacks `=`
  (`strava.rs:155`). The cookie store + the authed tile proxy are usable
  cross-origin, like H1 (`strava.rs:112`).
- To save a drawn plan does not invalidate `rideStats` (the StatsBar goes
  stale) (`MapView.tsx:1232`). Chunked `fetchRidesByIds` returns an
  interleaved order for >300 ids (`hooks.ts:115`). The bulk grade update
  swallows all failures (`DetailPane.tsx:166`).
